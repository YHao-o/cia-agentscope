# 修复多副本改造的三个遗留问题

## Summary

针对代码评审发现的 3 个问题做定向修复，不改变现有 fail-closed 语义：

1. **坏沙箱无自愈**：共享沙箱"活着但坏掉"（命令持续失败且非 SANDBOX\_NOT\_FOUND）时用户被卡死最长到映射 TTL（约 2h）
2. **续租零容忍**：Redis 一次瞬时抖动（>5s IO 超时）即判租约丢失，杀掉进行中的生成
3. **映射 TTL 与服务端 TTL 未对齐**：映射比沙箱服务端 TTL 晚几十秒过期，边界窗口内 connect 到已死沙箱报瞬时错误

## 现状（已确认的代码事实）

* [opensandbox\_workspace\_manager.py](f:\系统默认\桌面\workspace\综合智能应用门户\cia-agentscope\app\services\opensandbox_workspace_manager.py)：

  * `_reuse_local_entry`（L398-441）：共享模式下 `_prepare_shared_session` 非 gone 异常 → `_evict_locked` 后直接 `raise`，无自愈

  * `_connect_from_redis`（L443-474）：同样非 gone 异常 → `raise`

  * `_redis_publish_map`：`EX = int(self._ttl)`，发布晚于 `Sandbox.create(timeout=ttl)` 完成，映射必然比沙箱服务端 TTL 活得更久

  * 沙箱服务端 TTL 在 `_create_sandbox_raw` L300-306 以 `timeout=timedelta(seconds=int(self._ttl))` 一次性设定，创建后不延期

  * `COMPARE_DELETE` Lua 已从 redis\_lease 导入（比较值后删除）

## 修复方案

### 修复 1：坏沙箱自愈（opensandbox\_workspace\_manager.py）

**新增常量**（文件顶部参数区）：

```python
_PREPARE_RETRY_TIMES = 2      # 会话目录准备失败重试次数（判定"持续失败"前）
_PREPARE_RETRY_DELAY = 1.0    # 重试间隔（秒）
```

**新增方法** **`_prepare_with_retry(sbx, session_id)`**：包一层 `_prepare_shared_session`，失败（RuntimeError，即沙箱活着但命令失败）时重试 `_PREPARE_RETRY_TIMES` 次、间隔 `_PREPARE_RETRY_DELAY` 秒；SDK 异常（含 SANDBOX\_NOT\_FOUND）不重试直接抛。瞬时过载不再触发销毁。

**新增方法** **`_retire_shared_sandbox(wid, sandbox_id) -> bool`**：

```
1. RedisLease(sandbox_lock:{wid}, ttl=_DIST_LOCK_TTL, wait_timeout=5) 短等待
2. 拿不到锁 → 返回 False（其他 Pod 正在创建/处理，保持现状由调用方 raise）
3. 拿到锁后 GET sandbox_map:{wid} 复查：
   - != sandbox_id → 已被其他 Pod 替换 → 释放锁返回 True（调用方走 None 重建路径）
   - == sandbox_id → sbx = await Sandbox.connect(sandbox_id) → destroy（失败仅告警，服务端 TTL 兜底）
     → COMPARE_DELETE 删映射（值为 sandbox_id，不误删新映射）→ 释放锁返回 True
4. 全程 Redis 异常 → CoordinationUnavailable 向上抛（保持 fail-closed）
```

注意：`_retire_shared_sandbox` 内部的租约必须在返回前 `release()`——调用链在 `create_workspace` 持本地锁，随后第 3 步还要再拿 `sandbox_lock:{wid}` 建新沙箱，不释放会自等 30s 超时。

**改** **`_reuse_local_entry`**（L418-428 的 except 分支）：

```python
except Exception as exc:
    await self._evict_locked(wid)
    if self._sandbox_gone(exc):
        await self._redis_del_map(wid, entry.sandbox.id)
        return None
    # 持续失败：确认映射仍指向该沙箱后回收重建，卡死上限从映射TTL降为一次重试周期
    if await self._retire_shared_sandbox(wid, entry.sandbox.id):
        return None      # create_workspace 继续 → _connect_from_redis / 新建
    raise
```

其中 `_prepare_shared_session` 调用改为 `_prepare_with_retry`。

**改** **`_connect_from_redis`**（L457-463 的 except 分支）：同样模式——非 gone 时先 `_retire_shared_sandbox`，成功则 `return None`，失败（拿不到锁/Redis 异常）才 `raise`。prepare 同样换成 `_prepare_with_retry`。

**安全论证**：销毁前置条件 = 持有创建租约 + 映射仍指向该沙箱，双重确认后才 destroy + compare-delete，不会误删其他 Pod 刚发布的新映射；destroy 失败由服务端 TTL 收尾。

### 修复 2：续租与 watch\_stop 容忍瞬时抖动

**redis\_lease.py** **`_renew`**：

```python
async def _renew(self):
    failures = 0
    while True:
        await asyncio.sleep(max(0.01, self.ttl / 3))
        try:
            renewed = await asyncio.wait_for(...原 COMPARE_EXPIRE eval...)
        except asyncio.CancelledError:
            raise
        except Exception:
            failures += 1
            # 容忍 1 次瞬时抖动：失败后立刻重试一次（总预算 2 次续租周期内 10s+5s+5s < TTL 30s）
            if failures >= 2:
                logger.warning(...); self._mark_lost(); return
            continue   # 不 sleep，立刻重试
        if not renewed:
            self._mark_lost()   # 确定丢失（值被替换/删除）不重试
            return
        failures = 0
```

时序安全：TTL 30s、续租周期 10s、io\_timeout 5s——首次失败判于 \~15s、重试失败判于 \~20s 即 mark\_lost，此时 key 仍存活至 ≥30s，期间无其他持有者，无双跑窗口。

**chat\_runtime.py** **`watch_stop`**：加连续失败计数，3 次连续异常才 `cancel_event.set()`（单次/两次抖动继续轮询）。Redis 长时间不可用时租约 renew 也会失败 → on\_lost 置 cancel，兜底语义不变。

### 修复 3：映射 TTL 加安全边际

**`_PUBLISH_MAP`** **调用处**（`_redis_publish_map`，L174 附近）：`EX` 由 `int(self._ttl)` 改为

```python
_Map TTL = max(60, int(self._ttl) - _MAP_TTL_SAFETY_MARGIN)   # _MAP_TTL_SAFETY_MARGIN = 60
```

新增常量 `_MAP_TTL_SAFETY_MARGIN = 60`（模块顶部）。效果：映射先于服务端 TTL 至少 60s 过期，消除"connect 到已死沙箱"的错误窗口；代价是活跃用户沙箱在服务端销毁前 ≤60s 提前换新（换新透明：本地 entry 检查映射不一致 → evict → 重建，上传文件由自愈机制补回）。60s 同时覆盖 Redis 与沙箱服务端的时钟偏差。

## 不做的事

* 不改 fail-closed 总语义（Redis 真不可用仍 503/取消）

* 不动 charts、feedback\_service、chat.py 路由层

* 不给映射做"复用时续期"（服务端 TTL 本就固定自创建起算，续映射反而重新打开死沙箱窗口）
