# 质量标准、边界处理与常见文种

> 随时查用：写作判据、需求边界、FAQ、复盘规则、文种与篇幅对照。属查阅型内容，不必成稿前通读。

## 边界处理与主动问询

本技能必须主动识别并处理以下边界，不许"信息不够也硬写"：

**错误提示三段式**：发现用户输入或结果存在问题时，必须说清三件事——**哪里出问题了 → 为什么会错 → 怎么改**。例：“您提供的会议时间是10月，但引言写成'今年以来'，会议安排在年底会致该表述时效错位，请补一个开头一段话时间节点”。

**步骤可追踪**：核心工作流各环节推进时，输出关键节点要标注当前步骤（如【第3步·集素材】），让用户随时看到进度；中断续写时先报步骤再继续。

**故障自动恢复**：①素材文件读取失败→改用其他可读取方式提取内容，明确告知用户；②长文输出中断→从中断段落无缝续写，不重头来过；③用户中途改条件→仅重做受影响步骤，未受影响步骤的结果保留。

**防跳步检查**核心工作流六步不可跳步执行；面对用户追问、加需求等打断，先完成当前步并明确标记，再进入下一步，不可回应追问时跳过未完成的步。中断后接手续写时，先告知当前所处步骤再继续。

**小众场景声明**：用户提到未明确列入适用范围的文种或场景时，先明确声明"该场景属于本技能，将按通用框架处理"或"该场景超出范围"，不要默不作声地模糊处理。

| 情况 | 处理方式 |
|------|---------|
| 用户只给主题、没给场合/受众 | 主动追问背景、受众、类型、意图（见"领任务"） |
| 需求超出本技能范围（小说、营销文案、自媒体推文等） | 明确说明不在能力范围，并附上更合适的处理建议 |
| 需要引用文件/会议精神但用户未提供素材 | 先询问具体文件全称，宁问勿编造 |
| 关键数据模糊（"产值三个多亿"） | 保留【待确认：××】占位并标注，不自行补全 |
| 多份素材相互矛盾 | 逐条列出冲突点，请用户定夺后再动笔 |

## FAQ 与常见误区

**Q1：只给个题目，素材以后补，能先写吗？** 可以先出"通用骨架稿"，但所有需要事实支撑的段落用【待补充：××】标注，定稿前必须回替换。

**Q2：能不能就把这篇文章改一改给我用？** 不能整段沿用（有抄袭和穿帮风险）。正确做法是执行"智能搜索参考工作流"的五层借鉴法，只迁移结构、标题与论证方法。

**Q3：范文里引用的会议精神能照着写吗？** 不行。范文反映的是当时的写作背景，引用前必须核对官方原文，拿不准先问用户。

**Q4：一篇材料能多用金句吗？** 金句贵在"一稿一两句"，堆多了反而落入套路。

**Q5：命令、议案这些很少用的法定公文，能写吗？** 能，但这类文种发文层级高（命令、公报多为中央层），实际动笔前先向用户确认发文机关层级与文种是否选对了——很多单位该用"通知/通报"的场合容易混用。

**新手常见误区**：①标题堆砌对仗但不贴内容；②通篇"高度重视"式的口号没有具体动作；③滥用"总之""综上所述"等 AI 腔套路词；④硬造无内涵的排比假金句；⑤素材一一陈列而没有主线；⑥讲话稿不按 250-300 字/分钟 反推篇幅；⑦模糊处靠猜不写"待确认"。

## 复盘沉淀机制（用户追问 = 质量信号）

用户在成稿交付后的追问、要求重写或返工，说明当前产出未达预期，必须按以下机制处理：

1. **识别信号**：交付后的追问（"这个标题太套路""这个数据哪来的""再改改"）是质量反馈而非新任务；先确认问题点，再定位改进方向，同时启动重写。
2. **沉淀一条学习**：每次追问最多沉淀 **1 句话**（≤40 字），格式为"场景 + 教训"，如"心得体会开头忌堆砌套话，用户更看重具体感受"。不做长篇复盘。
3. **存量上限 10 句**：学习条目累计超过 10 句时，合并同类项、淘汰最旧与最低频条目，始终保持 ≤10 句。
4. **沉淀位置**：写入会话记忆系统的经验教训类页面；无记忆系统时写入工作区文件 `output/公文写作学习沉淀.md`。下次同场景写作前先读取并应用。
5. **闭环**：沉淀后向用户一句话确认已记录，并在本次重写中立即体现改进。

## 写作质量标准

一篇好的公文或讲话稿，需同时满足两个标准：

### 标准一：领导点头（让领导满意是出发点）
- **谋到位**：站在领导角度思考，"身在兵位，胸为帅谋"
- **想到位**：善于揣摩领导意图——从批示中、从讲话风格中、从关注重点中把握
- **跟到位**：身跟（多参会、多调研、多记录）+ 心跟（留意领导宣读时的卡壳处，那是不满意的地方）

### 标准二：阅者点赞（"三个有、三个一"）
- **有思想性**——让人"眉头一皱"：有认识上的提高、观念上的更新、理性上的思考
- **有针对性**——使人"心头一紧"：问题要实、短板要准，引发思考、感到压力
- **有新鲜感**——令人"眼前一亮"：有金词金句、亮眼标题、酣畅淋漓的表达

## 写作方法论

三条不可动摇的原则：

1. **立意有高度**：引述上级论述和政策文件 → 立足全局角度 → 借鉴先进经验
2. **内容有深度**：一篇成功的讲话稿就是"这篇稿子只能在这个会议上用"，即便同一主题也能写出不同
3. **表述有温度**：朴实鲜活、平易近人，穿插俗语、歇后语等接地气语言

## 常见文稿类型的快速指引

当用户未明确文稿类型时，根据场景判断：

| 场景 | 推荐文稿类型 | 结构要点 |
|------|-------------|----------|
| 工作会议 | 专题工作类讲话 | 形势分析→安排部署→保障要求 |
| 座谈研讨 | 研讨发言类 | 认识体会→问题分析→意见建议 |
| 年终/阶段性 | 工作总结 | 成效→做法→问题→打算 |
| 欢迎/欢送/开幕 | 致辞 | 问候→背景→意义→祝愿 |
| 向上级汇报 | 工作汇报 | 基本情况→主要做法→存在问题→下步打算 |
| 经验交流 | 典型发言 | 引入→经验做法（核心）→展望收尾 |
| 对外宣传/媒体报道/信息稿 | 工作通讯 | 群众引语开头→背景→分板块做法（含硬数据）→负责人引语收尾，见 `essays/真实成稿-宣传通讯.md` |
| 年终盘点/公众号年度推文/答卷体 | 年度盘点 | 导语（三字对）+ "双字动词丨八字主题"×N条 + 抒情收尾，见 `essays/真实成稿-年度盘点.md` |
| 交流锻炼/跟班学习结束 | 交流锻炼心得 | 典故+现场细节开篇→体验/理念/行动三段递进，见 `essays/真实成稿-交流心得.md` |
| 支部/小组小型会议个人发言 | 小型会议发言（心得/研讨/表态） | 见"一般工作人员小型会议发言工作流" |
| 正式发文 | 法定公文 | 严格按《党政机关公文处理工作条例》规范（15 种：决议、决定、命令[令]、公报、公告、通告、意见、通知、通报、报告、请示、批复、议案、函、纪要） |
