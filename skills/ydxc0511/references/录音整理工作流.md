# 录音与素材自动整理工作流

> 用户上传音频或未整理素材时读本文件；只做整理成稿所需的步骤，不预读其他工作流。

## 录音与素材自动整理工作流

当用户上传**音频文件**（会议录音、领导讲话、访谈录音等）或**未整理的文字素材**（速记稿、语音转文字稿、零散笔记、会议记录等），要求"整理成公文""生成纪要""转成讲话稿"时，按以下流程处理。

### 第 0 步：素材接收与转写

- **识别输入类型**：先判断是音频文件还是未整理文本，不同类型走不同处理路径。
- **音频转写**：调用可用的语音转文字能力（如 Whisper、飞书妙记、通义听悟等）将音频转为文本。转写时注意：多人发言尽量区分说话人；方言、专业术语、人名地名需校正；转写稿口语化严重，需先做初步清洗。
- **文本预处理**：对转写稿或原始素材做初步清洗——去除重复语句、语气词（"嗯""啊""那个""就是说"）、明显的转写错误。

### 第 1 步：内容解构

- 通读全文，识别主题与逻辑主线。
- 按主题对碎片化内容聚类分段。
- 提炼"三要素"：每个板块提炼出**核心观点、关键数据、具体举措**。
- 标注模糊点：人名、数字、专有名词等不确定处，整理后须向用户确认，不得臆造。

### 第 2 步：确认文稿类型

- 优先询问用户：这份素材要生成什么类型的文稿？（讲话稿、会议纪要、工作汇报、通知、工作总结等）
- 用户未明确时，根据素材场景自动判断（参照"常见文稿类型的快速指引"）：
  - 会议录音 → 通常生成**会议纪要**或**讲话稿**
  - 领导讲话 → **讲话稿**
  - 汇报发言 → **工作汇报**
  - 调研座谈 → **调研报告**

### 第 3 步：套用 123456 框架成稿

将解构出的要点代入核心工作流的六个步骤：

1. **领任务**：明确背景、受众、类型、意图
2. **列提纲**：根据素材要点搭建框架（复用七种标题方式）
3. **集素材**：以素材内容为主体，补充上情（政策依据）、实情（具体工作）、真情（接地气表达）
4. **写正文**：将口语化要点转化为规范公文语言
5. **善润色**：去口语化、规范化、精炼化，穿插金句
6. **呈定稿**：三审校稿，并向用户确认模糊点

### 去口语化对照表

| 口语表达 | 公文表达 |
|---------|---------|
| 我们觉得 / 我寻思 | 会议认为 / 我们认为 |
| 干得不错 / 干得挺好 | 成效明显 / 进展顺利 |
| 搞了好几个项目 | 实施了一批重点项目 |
| 接下来要 / 后面要 | 下一步将 / 下阶段要 |
| 挺重要的 / 特别重要 | 意义重大 / 至关重要 |
| 那个啥 / 就是说 / 然后 | （删除） |
| 抓紧弄 / 赶紧办 | 加快推进 / 抓紧落实 |

### 整理原则

- **忠实原意**：整理不是创作，不添加素材中不存在的事实和数据。
- **宁缺毋滥**：模糊内容标注"待确认"，不臆造。
- **结构优先**：先搭框架、再填内容，避免流水账。
- **保留风格**：讲话人的核心观点、金句、惯用表达可适度保留，体现个人风格。
